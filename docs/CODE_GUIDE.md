# Понятия и порядок чтения исходников

Заголовки собственных C/C++/header/.def-файлов содержат `@file`, назначение и
короткие определения используемых понятий **на английском языке**. Это относится и
к inline-комментариям, CMake, тестам и вспомогательным скриптам. Markdown-документация
Quanta пишется **на русском**; имена API, метрик и команды не переводятся.

Исходники и лицензии сторонних библиотек GLFW/ImGui, их собственная документация и
reference-копии сохраняются без изменений, на языке оригинала. Описания их интеграции
в `vendor/GLFW.md`, `vendor/IMGUI.md`, `vendor/PORTABLE_GUI.md` — русские.

Исходный текст собственных программ — ASCII. Для Unicode-тестов используются escapes.
Генератор `tools/embed_docs.py` сохраняет русские Markdown-данные в C как массивы
байтов UTF-8 в шестнадцатеричной записи; при `quanta describe` пользователь получает исходный русский текст.
Тест `source_contract` проверяет это правило для исходников, `documentation` — актуальность
генерации, а CLI-тест — совпадение встроенного текста с Markdown.

| Понятие | Значение в текущем Quanta |
|---|---|
| Metric | Дескриптор измерения: уникальное имя, тип, единица, политика и callbacks. Не само число. |
| Catalog | Неизменяемый набор metric descriptors. Не база измерений и не список providers. |
| Instance / labels | Экземпляр источника и пары ключ/значение: конкретное CPU, NIC, датчик. |
| Series | Измеряемая последовательность с идентичностью источника. Смена устройства может менять series ID. |
| Sample | Значение серии + время, status, quality; ошибка не равна корректному нулю. |
| Plan | Разобранный query: select, интервалы, история, HAL, режим и оформление. |
| Snapshot / acquisition | Одна общая операция получения нескольких полей. Не выбираемая пользователем абстракция. |
| Sink | Callbacks приёмника уведомлений ядра: начать, серия, кадр, отсчёт, ошибка, завершение. |
| Event | Копия уведомления sink в очереди worker→UI. Это не реализованная подписка на внешнее событие ОС. |
| History / model | Ограниченная история и состояния последнего/последнего успешного значения. |
| HAL | Низкоуровневые аппаратные операции с capabilities и политикой доступа. |
| OSAL | Минимальный runtime; не источник CPU load/PDH/working set. |
| Frontend / backend | Представление метрик / реализация окна, ввода и рисования. |
| Framebuffer | Массив RGB-пикселей в RAM; отдельный слой показывает его в native-окне. |

## Прочитать сначала

`include/quanta/types.h` → `metric.h` → `registry.h` → `query.h` → `engine.h`.
Затем `core/src/registry.c`, `engine.c`, `discovery.c`, `scheduler.c`.
Для UI-потока — `core/src/live.c` и `history.c`: здесь важны владение данными,
ограничение очереди и остановка до уничтожения engine.

## Проследить одну метрику

Например, `metrics/memory.def` задаёт имя/тип/единицу и callbacks.
`sensors/os/memory_metrics.c` управляет снимком и извлекает нужное поле.
`sensors/os/linux/memory.c` или `windows/memory.c` выполняет конкретный native-сбор.
`sensors/registry.c` добавляет descriptor в каталог; core не включает его напрямую.

## Проследить GUI

`frontends/gui/gui.cpp` строит одни и те же виджеты и работает с live/model.
`backend.h` отделяет окно/renderer. CMake выбирает `opengl.cpp` **или** `framebuffer.cpp`.
Во framebuffer `imgui_renderer.cpp` ведёт текстуры и команды,
`portable_quad.cpp` ускоряет подходящие пары треугольников, `raster.c` рисует остальные.
`window.h`/`x11.c`/`windows.c` отвечают только за presentation и native input.
Ни одна из этих частей не определяет значение CPU/RAM-метрики.
