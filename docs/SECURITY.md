# Безопасность и границы доверия

Inv — локальная read-only утилита, не сервис и не привилегированный агент. Нет
телеметрии, сетевой отправки отчётов, загрузки плагинов, shell execution,
установки драйвера, доступа к /dev/mem или записи в sysfs. Единственные намеренные
записи пользовательских данных — выбранный новый output файл; TUI меняет состояние
терминала и восстанавливает его; GUI общается с локальным X-сервером.

Не устанавливайте setuid/file capabilities. DMI-ошибки доступа допустимы. Если
для конкретного текстового отчёта требуются административные права, оцените это
отдельно; GUI от root не нужен. Чтение опасного/неисправного драйвера может
блокироваться: универсальный hard timeout в этой версии отсутствует.

Запросы ограничены по размеру, типизируются до исполнения и не могут указывать
произвольные sysfs-пути. Имена/значения/пакеты ограничены; длинный результат даёт
LIMIT вместо незаметного усечения. Данные ядра и firmware не считаются HTML/
терминальными командами. CSV защищает потенциальные formula strings по умолчанию.

XCB использует обычную X11 модель доверия: cookie предоставляет доступ к серверу,
не sandbox между клиентами. Нельзя отключать X11 authentication ради запуска.
Поддерживается только локальное соединение, не TCP и не SSH DISPLAY.

Для больших запросов действуют пределы количества серий и истории. При медленном
UI коллектор получает backpressure. Пользовательские файлы шрифтов и внешний
X-сервер всё равно являются дополнительными входами; при работе с недоверенными
источниками выбирайте FILE/TUI и непривилегированный процесс.

Сборка GUI загружает зависимость только на этапе конфигурации, никогда во время
работы inv. Pin ревизии, TLS, provenance и offline-сборка описаны в BUILD.md.
