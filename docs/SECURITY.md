# Безопасность аппаратного доступа

Штатные метрики read-only. CLI не повышает привилегии, не загружает драйверы/modules, не запускает
внешние monitor utilities и не включает write-capabilities. Default HAL — native, не linux-dev.
`hal-info` не выполняет physical/register/PCI reads. Неизвестный HAL не заменяется другим.

HAL write entrypoints существуют для будущего embedding, но требуют явного ALLOW_WRITE при
создании handle. Read operations тоже могут иметь побочные эффекты на MMIO; нет гарантии
безопасности произвольных физических адресов и атомарности. Allowlist ограничивает диапазоны,
но не доказывает безопасную семантику самого устройства. Не подавайте недоверенные адреса.

Capabilities означают наличие callbacks, не разрешение ОС. Permission errors и отсутствие
устройства публикуются как status, не как успешный ноль. Наличие записи в registry не требует
привилегий; `list --probe` уже действительно запускает выбранные метрики.

ESP GPIO 6–11 исключены, остальные пины не перенастраиваются автоматически. VDD33 disabled
по умолчанию: его включение требует проверки подключения TOUT и PHY config. Нельзя использовать
профиль чужой платы без проверки flash size/mode, XTAL и pin wiring.

Redaction — для SENSITIVE values; это не универсальная анонимизация labels/titles/diagnostics.
Файлы output создаются эксклюзивно без молчаливого overwrite. Query/label/value размеры ограничены;
CRC/hash или криптографическая защита blob пока не заявляются, поскольку blob формата ещё нет.

Тесты HAL используют только собственные временные файлы/RAM. Native affinity тест временно
прикрепляет свой поток в рамках разрешённой mask и восстанавливает её. Реальные memory/MSR/PCI
hardware writes не входят в автоматическую сборку или тестирование.
