# Проверка Quanta 0.8.0

## Фактически выполненные сборки

Среда проверки: Linux (Debian 13), GCC 14.2, Clang 17, CMake 3.31.6,
заголовки X11 и Xvfb. Это версии стенда, а не новые требования к установке.
Во всех перечисленных конфигурациях предупреждения собственного кода считаются ошибками.

| Конфигурация | CTest | Что проверено |
|---|---:|---|
| GCC Release, FRAMEBUFFER + TUI | 19/19 | Полный набор, настоящее окно на Xvfb |
| GCC Debug, FRAMEBUFFER + TUI | 19/19 | Включая растеризатор и его управление ресурсами |
| Clang Debug, FRAMEBUFFER, ASan + UBSan | 19/19 | Обнаружение утечек включено; ошибок в выполненном прогоне нет |
| Linux без GUI, все метрики текущей ОС + TUI | 17/17 | Приложение без графических/C++-зависимостей |
| Минимальный Portable POSIX | 10/10 | Минимальная среда исполнения, настоящее ядро/query/файл |
| FRAMEBUFFER без обнаружения Python | 13/13 | Только зарегистрированные C/C++-тесты |
| Статическая Linux-сборка без GUI | 17/17 | Дополнительно отсутствуют PT_INTERP и DT_NEEDED |

Полная сборка сама запускает CTest. Release/Debug framebuffer проверены также отдельным
повторным CTest. Число тестов зависит от конфигурации и наличия Python/Xvfb: меньший набор
не означает, что необязательные проверки были выполнены.

`imgui_renderer` проверяет 51 условие: Alpha8/RGBA32, частичное обновление текстур,
динамический шрифтовый атлас, VtxOffset, освобождение ресурсов и результат рисования.
Проверен быстрый путь прямоугольников из portable_gui и переход к общему растеризатору
для неподходящей геометрии. Тест `gui` запускает настоящее окно, дожидается завершения
конечного query, проверяет ошибку отсутствующего дисплея и очистку после отсутствующего
файла шрифта. Эти сценарии прошли и под ASan/UBSan.

[Снимок настоящего окна версии 0.8.0](assets/gui-framebuffer-linux.png) сделан с
FRAMEBUFFER на Xvfb. Это не макет и не изображение OpenGL-ветки.

## Язык исходников и сохранность поведения

Проверены **175 заголовков собственных C/C++/H/DEF-файлов**: назначения файлов и
объяснения понятий переведены на английский, а не удалены. Тест `source_contract`
контролирует **232 собственных исходных/сборочных/тестовых файла** на отсутствие
не-ASCII-текста. Это практическая проверка от случайного возвращения кириллицы, а не
автоматическое доказательство качества английского перевода. Имена из сторонних
лицензий и оригинальные исходники библиотек из этой проверки исключены.

Для **173 из 175** C/C++/H/DEF-файлов проверено полное совпадение лексических единиц
с 0.7.0 после исключения комментариев и пробелов. Два ожидаемых исключения:
`include/quanta/types.h` содержит новую версию, а `sensors/metric_docs.c` — русскую
документацию. Все объявления `.def`, имена и версии метрик, callbacks и вычислительные
реализации сохранены. Все девять MCU-ключей остаются активными.

Дополнительно выполнено:

- 15 публичных заголовков независимо компилируются в C11 и C++17;
- исходный `docs/Quanta_Design.md` побайтно совпадает с предыдущей поставкой;
- все собственные Python-файлы проходят синтаксическую проверку;
- контрольная вставка кириллического комментария отклоняется `source_contract`;
- после восстановления исходника весь контроль структуры проходит снова.

## Русская встроенная документация

Все **93 документа метрик** встраиваются без изменения UTF-8-байтов. Генератор
`tools/embed_docs.py` записывает массивы байтов с завершающим NUL: исходник C остаётся
ASCII, не зависит от кодовой страницы компилятора и не использует чрезмерно длинные
строковые литералы. Проверено побайтное совпадение каждого массива с соответствующим MD.

CLI-тест также сравнивает вывод `describe` с MD для всех метрик, вошедших в каталог
текущей конфигурации. В минимальной сборке без встроенной документации этот раздел
проверки явно не применяется. Чтение файлов тестовыми скриптами выполняется с явной
кодировкой UTF-8, а не с системной локалью Windows.

## GLFW: включение и границы проверки

Включены **все 167 файлов** предоставленного `glfw-3.4.zip`; они побайтно совпадают с
архивом. `source_contract` проверяет перечень и SHA256 каждого файла по
`vendor/GLFW.sha256`. Контрольное изменение заголовка GLFW было обнаружено; затем файл
восстановлен и проверка повторена успешно. Исходные файлы ImGui и portable_gui reference
также сохранены без изменений. Подробности — [GLFW](../vendor/GLFW.md),
[ImGui](../vendor/IMGUI.md), [portable_gui](../vendor/PORTABLE_GUI.md).

Настоящие исходники GLFW собраны в статическую библиотеку с **Null platform**.
Отдельная программа проверила версию 3.4.0, инициализацию, создание объекта окна без
графического API, размер, признак закрытия и освобождение ресурсов. Null platform
не создаёт системное окно или OpenGL-контекст: это проверка зависимости, не GUI-приёмка.

Для `frontends/gui/opengl.cpp`, `imgui_impl_glfw.cpp`, `imgui_impl_opengl3.cpp` выполнена
синтаксическая проверка Clang C++11 с **настоящим включённым заголовком GLFW 3.4**.
Из-за отсутствия системного GL development-пакета объявления OpenGL взяты из включённого
в ImGui загрузчика. Это не обычная окончательная компиляция с заголовками системы,
не линковка GUI-программы и не запуск контекста OpenGL.

На проверочном Linux отсутствуют пакеты разработки GLFW/OpenGL; установить их через
сеть не удалось. Обычный CMake без параметров действительно выбирает OPENGL и завершился
ожидаемой ошибкой о недостающем `libglfw3-dev`, не переключаясь незаметно на CLI.
В Windows исходники GLFW теперь уже находятся в репозитории: дополнительная загрузка
не требуется, и прежний шаг CI с предложением скачать их удалён.

**Не выполнены:** полноценная сборка/запуск Linux OpenGL, нативная Windows MSVC/WinAPI
для обоих графических backend, настоящая сборка ESP8266 SDK/Xtensa и проверка платы.
Подготовленная CI-матрица не считается запущенной проверкой. ESP-тесты используют
подмену SDK-вызовов на компьютере, а не имитируют успешную прошивку устройства.

## Как повторить

```bash
cmake -S . -B build/framebuffer -DQUANTA_GUI_BACKEND=FRAMEBUFFER
cmake --build build/framebuffer --parallel
ctest --test-dir build/framebuffer --output-on-failure

cmake --preset linux-no-gui
cmake --build --preset linux-no-gui --parallel
ctest --preset linux-no-gui --output-on-failure
```

Для полного набора дополнительных проверок нужен `python3`, для проверки окна —
`Xvfb`. Для OpenGL выполнить обычные команды README после установки системных пакетов
Linux; в Windows GLFW уже включён. Значения `--config` и `ctest -C` должны совпадать.
Для ручной приёмки остаются масштабирование/DPI, изменение размера окна, ввод/буфер
обмена, пользовательский шрифт, драйвер OpenGL и длительный сеанс.

Окончательный ZIP отдельно проверяется по CRC и MANIFEST.sha256, распаковывается в новый
каталог с пробелами и собирается обычным CMake с **явным FRAMEBUFFER**, без preset и
без Ninja. Лог этой проверки поставляется рядом с архивом. Она не обозначается
как успешная сборка OpenGL по умолчанию.
